## Contributing

First off, thanks for your interest in contributing to Peepaway!

Peepaway is an open-source "travel" platform, and contributions of all kinds are welcome, including code, design improvements, bug reports, documentation, feature suggestions and whatever you may come up with.

## Getting Started

1. Check the [open issues](https://github.com/deobibila/peepaway/issues) to find something you'd like to work on.
2. Fork the repository to your GitHub account.
3. Clone your fork locally.
4. Create a branch for your changes.
5. Make your changes and test them.
6. Push your branch and open a pull request against Peepaway's `main` branch.

## Development Workflow

Use descriptive branch names, such as:

- `feature/trip-dashboard`
- `fix/flight-search`
- `feature/flight-alerts`
- `docs/update-readme`

Write clear commit messages explaining your changes.

Before submitting a pull request, make sure your code works, follows the project's existing conventions, and includes relevant tests where appropriate.

## Pull Requests

When opening a pull request, please:

- Explain what you changed and why.
- Link any related GitHub issues.
- Include screenshots for visual changes.
- Describe how you tested your changes.
- Keep pull requests focused on one feature or fix whenever possible.

All pull requests are reviewed before being merged. Maintainers may request changes or suggest improvements.

## Reporting Bugs and Suggesting Features

Found a bug or have an idea?

Open a [GitHub issue](https://github.com/deobibila/peepaway/issues) and describe it clearly.

For security vulnerabilities, please follow our [Security Policy](docs/SECURITY.md) rather than opening a public issue.

## Code of Conduct (Short Version)

Be respectful, constructive, and welcoming to other contributors.

We're here to build something helpful!
